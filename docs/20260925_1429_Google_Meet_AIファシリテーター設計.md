# Google Meet AI ファシリテーター 設計

作成日: 2026-09-25
実装: `packages/meet_facilitator/`

## 1. 目的

チームみらいが開発している「ゆる語りワークショップ」は、意見が割れる問いに対して A / B に投票し、
AI インタビュー → 同じ側での共有 → 違う側との対話、という流れで合意点・相違点を探るツールである。

本設計は、その体験を **Google Meet の中に組み込み**、さらに「A か B かを選ぶ」ことではなく
**双方が納得できるプランCをつくる** ことをゴールに置き、その導き役（ファシリテーション）を AI に担わせるものである。

- 参加者の発言をリアルタイムに文字起こしする
- A 側・B 側それぞれの主張と、その裏にあるニーズを言語化する
- 共通点を可視化し、次に話すべき問いを場に投げかける
- 材料が揃ったら、双方の関心を満たすプランCの叩き台を提示し、残論点を絞る

## 2. Google Meet に組み込む手段の整理

| 手段 | 状態 | できること | できないこと |
| --- | --- | --- | --- |
| Meet Add-ons SDK | 一般提供 | サイドパネル／メインステージに自作 Web アプリを表示。全員に同期表示する共同作業（`startActivity`）。frame 間メッセージ | 音声・映像へのアクセス |
| Meet Media API | デベロッパープレビュー | 会議の音声・映像をリアルタイム受信 | プロジェクト・OAuth 主体・参加者全員のプレビュー登録が必要で、一般公開できない |
| ミーティングボット（Recall.ai 等） | 利用可 | ボットを参加者として入室させ、音声とリアルタイム文字起こしを Webhook で受信 | ボットが参加者として見える（ただし透明性の面ではむしろ利点） |

結論: **画面は Meet Add-on、音声はボット**で実装し、Meet Media API が一般公開されたら音声取得だけ差し替える。
差し替えを容易にするため、音声→文字起こしの供給源は `TranscriptSource` インターフェースで抽象化した。

## 3. ワークショップの流れ（フェーズ）

```
lobby → vote → interview → share → cross → plan_c → closed
```

| フェーズ | 内容 | 画面 | AI の役割 |
| --- | --- | --- | --- |
| lobby | 参加者が集まる | 問いと参加者一覧 | — |
| vote | A / B に投票 | サイドパネルで投票、メインステージに集計と誰が何に投票したか | — |
| interview | 一人ずつ AI インタビューに答える | サイドパネルのチャット | 理由・経験・相手側への理解を短い質問で引き出す |
| share | 同じ側同士で共有 | 同じ側のグループ表示 | 各側の主張の要点整理 |
| cross | A と B が混ざって対話 | 混合グループ、AI の問い、共通点／相違点 | 文字起こしから共通点・相違点・裏のニーズを可視化し、次の問いを出す |
| plan_c | プランCを磨く | 叩き台、A/B それぞれの関心を満たす点、残論点 | 双方の関心を満たす案を提案し、残論点を絞る |
| closed | 終了 | 最終案 | — |

ブレイクアウト（share / cross の小グループ）は Meet 標準のブレイクアウトルームを使い、
各ルームにボットを入れる。文字起こしセグメントは `room` を持てるようにしてある。

## 4. アーキテクチャ

```
Google Meet
├─ Add-on サイドパネル (web/sidepanel.html)  ── 投票・AIインタビュー・進行操作
├─ Add-on メインステージ (web/mainstage.html) ── 全員向け表示（集計・AIの問い・共通点・プランC）
└─ ボット参加者 (Recall.ai) ── 音声 → リアルタイム文字起こし ── Webhook ──┐
                                                                          ▼
                                                        Hono サーバー (src/server)
                                                        ├─ SessionStore（状態機械・投票・文字起こし）
                                                        ├─ FacilitationEngine（入力組み立て・自動再実行判定）
                                                        └─ FacilitatorModel
                                                           ├─ ClaudeFacilitatorModel（構造化出力）
                                                           └─ MockFacilitatorModel（オフライン）
```

### 4.1 ドメイン（`src/core`）

- `Session`: 問い、フェーズ、参加者、投票、文字起こし、インタビュー、ファシリテーション履歴、`version`
- `SessionStore`: インメモリ。`vote` は vote フェーズのみ、参加者以外の投票は拒否、といった不変条件をここで守る
- `FacilitationEngine`: セッション状態から LLM 入力を組み立て、結果を記録する。Next.js／HTTP に依存しない
  - 自動再実行ポリシー: 対象フェーズ（share / cross / plan_c）で、前回から 200 文字以上増えた、または 45 秒以上経過して新しい発言がある
  - 同一セッションの同時実行は防ぐ

### 4.2 LLM 層（`src/llm`）

- `FacilitatorModel` インターフェース: `facilitate(input)` と `interview(input)`
- `ClaudeFacilitatorModel`: `@anthropic-ai/sdk` の `messages.parse` + `zodOutputFormat` で構造化出力を受け取る
  - 既定モデル `claude-opus-5`、adaptive thinking、`effort: medium`（リアルタイム性重視。環境変数で変更可）
  - システムプロンプトは固定文字列にして `cache_control` でプロンプトキャッシュを効かせる
  - `stop_reason: refusal` は例外にして呼び出し側で扱う
- 出力スキーマ（`FacilitationOutput`）: 要約、A/B の主張、共通点、相違点（裏のニーズ付き）、次の問い、発言を促す人、プランC（status / 本文 / A・B それぞれの満たす点 / 残論点）

### 4.3 文字起こし（`src/transcript`）

- `TranscriptSource` インターフェース
- `recall.ts`: Recall.ai のボット作成と `transcript.data` Webhook のパース（形状は公式ドキュメントで最終確認が必要）
- `scripted.ts`: 台本を流すデモ用

### 4.4 HTTP API（`src/server/app.ts`）

REST + ポーリング（`GET /api/sessions/:id?since=version` → 変化がなければ 304）。
プロトタイプでは SSE/WebSocket より単純で、Meet の iframe 内でも確実に動く。

### 4.5 画面（`web/`）

バンドラなしの素の ES Module。Meet Add-ons SDK は `node_modules` からそのまま `/vendor/meet.addons.mjs` で配信する。
Meet の外で開いた場合は SDK 初期化に失敗して standalone モードになり、`?session=` でセッションを指定する。

セッション ID は Meet の `meetingCode` を使う。これにより同じ会議の参加者は自動的に同じセッションに入る。
メインステージは `startActivity({ mainStageUrl, additionalData })` で全員に開く。
