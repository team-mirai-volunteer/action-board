# データ分析基盤（BigQuery）へのEメール連携

## 目的

アクションボード登録の全ユーザーについて、データ分析基盤（BigQuery）で以下を利用できるようにする。

- 個人ID（ユーザーUUID）
- 都道府県
- **メールアドレス**（今回追加）

最低限、**個人ID + メールアドレス**が連携できれば要件を満たす。

## 現状のパイプライン構成

BigQuery へのデータ連携は **PostgreSQL の論理レプリケーション** で行っている。

- publication: `bq_pub`（`FOR ALL TABLES`）
- レプリケーションスロット: `bq_slot`（`pgoutput`）
- 読み取りユーザー: `bq_user`（`REPLICATION` / `BYPASSRLS` / public スキーマの `SELECT`）
- 定義: `supabase/migrations/20250620122832_bigquery_replication_setup.sql`
- 参考: https://tech.asahi.co.jp/posts/20250214-197e

各データの所在は次の通り。

| 項目 | テーブル | スキーマ | 連携状況（従来） |
| --- | --- | --- | --- |
| 個人ID | `public_user_profiles.id`（= `auth.users.id`） | public | 連携済み |
| 都道府県 | `public_user_profiles.address_prefecture` | public | 連携済み |
| メールアドレス | `auth.users.email` | **auth** | **未連携** |

## なぜメールが連携されていなかったか

ID・都道府県は `public` スキーマの `public_user_profiles` にあり、既に連携対象に入っている。
一方メールアドレスは **`auth` スキーマの `auth.users.email`** にあり、取り込み対象に含まれていなかったため分析基盤に届いていなかった。

`#2192`（`20260402000000_grant_bq_user_auth_users.sql`）で `bq_user` に `auth.users` の
SELECT 権限は付与済みだが、それだけでは取り込み側の対象に `auth` スキーマが入っていないと
メールは流れてこない。

## 今回の変更（このPR）

方針: **`auth.users` を直接連携する**（public 側に中間テーブルを作らない）。

### DB 側（本リポジトリで完結する部分）

`supabase/migrations/20260716000000_connect_auth_users_email_to_bq_pipeline.sql` を追加し、
DB 側の連携設定を冪等かつ明示的にした。

1. `bq_user` の `auth.users` 読み取り権限を再付与（`#2192` と同内容。全環境で確実に有効化）
2. `auth.users` が publication `bq_pub` に含まれることを保証
   - `bq_pub` が `FOR ALL TABLES` の場合は既に `auth.users` を含むため何もしない
   - テーブル列挙型の publication だった場合のみ `ALTER PUBLICATION bq_pub ADD TABLE auth.users`

REPLICA IDENTITY は変更しない。`auth.users` は主キー（`id`）を持つため、
INSERT / UPDATE（メール変更）/ DELETE いずれも既定の replica identity で
現行のメールアドレスを捕捉できる（`FULL` にすると WAL 量が増えるため不要）。

### 取り込み側（外部・別途必要）

実際に BigQuery へ取り込む外部の取り込み側（Datastream 等）の設定で、
レプリケーション対象に **`auth` スキーマ / `auth.users`** を追加する必要がある。
この設定は本リポジトリの外にあるため、以下を別途実施する。

1. 取り込みストリームの対象オブジェクトに `auth.users`（または `auth` スキーマ）を追加
2. 追加後、初回バックフィル + CDC でメールアドレスが BigQuery に反映されることを確認

## BigQuery 側での結合（利用イメージ）

ID をキーに `public_user_profiles`（都道府県）と `auth.users`（メール）を結合する。

```sql
SELECT
  p.id                 AS user_id,
  u.email              AS email,
  p.address_prefecture AS address_prefecture
FROM `<dataset>.public_user_profiles` AS p
LEFT JOIN `<dataset>.users`           AS u  -- auth.users を取り込んだテーブル
  ON p.id = u.id;
```

## セキュリティ・プライバシー上の注意

- `auth.users` を直接連携すると、`email` だけでなく `encrypted_password`（ハッシュ）、
  各種トークン列（`recovery_token` 等）を含む **全カラム** が BigQuery 側に流れうる。
  BigQuery データセットのアクセス権限を必要最小限に絞ること。
- 取り込み側で列の除外（カラム除外）が可能なら、`email` と `id` など必要な列だけに
  絞ることを推奨する。
- メールアドレスは個人情報のため、分析基盤側でも取り扱い範囲・保持期間を明確にすること。

## 検証方法

DB 側（Supabase / Postgres）:

```sql
-- bq_user が auth.users を読めるか
SELECT has_table_privilege('bq_user', 'auth.users', 'SELECT');  -- => true

-- auth.users が publication に含まれるか
SELECT schemaname, tablename
FROM pg_publication_tables
WHERE pubname = 'bq_pub' AND schemaname = 'auth';  -- => auth / users が返る

-- publication の種別
SELECT pubname, puballtables FROM pg_publication WHERE pubname = 'bq_pub';
```

BigQuery 側:

- `auth.users` 由来のテーブルに `email` が入っていること
- 上記結合クエリで ID + メール + 都道府県が揃うこと
