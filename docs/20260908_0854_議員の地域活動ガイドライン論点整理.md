# 議員の地域活動ガイドライン 論点整理

## 概要

「議員の地域活動はどうあるべきか？」について、現時点の叩き台（現行案）と、それに対する懸念（対案）を並べ、論点ごとに整理した上で統合案を提示する。最終決定のための材料であり、決定事項ではない。

対象読者: 組織活動本部、議員、サポーター向け説明を作る担当者

## 1. 背景と前提

- チームみらいは **デジタル民主主義（デジ民）の実践** を活動の中心に置く。選挙で勝つこと自体を目的にしていない。
- サポーターは「デジ民の実践」に参加するために集まっており、議員個人の後援会員ではない。
- 議員は地域に顔が広く、地域の人から声をかけられると断りにくい。放っておくと従来型の地域政治（街頭・チラシ・祭りへの顔出し）に自然と流れる構造がある。
- オフラインイベントの企画・運営は組織活動本部が担っており、議員をイベントにアサインする体制はすでにある。

## 2. 現行案（叩き台）

1. デジ民を実践する取り組みであれば、地域での活動も **推奨** する。
   - サポーターを巻き込む場合は、事前に組織活動本部に確認をとる（トラブル時のクイック対応、サポーターとのコミュニケーション上の注意点の共有のため）。
   - 結果は組織活動本部にシェアする（ベストプラクティスを集約するため）。
   - 例: サポーター主催の「ゆる語りWS」に顔を出す／議員主催でデジ民プロダクトを使うイベントを開く。
2. デジ民の実践ではない活動は **禁止しないが、評価の対象にはならない**。
   - 例: 街頭演説、チラシ配り（デジ民イベント告知のチラシ配りは理論上評価対象だがROIは低い）。
   - 地域の祭りに顔を出すだけでは評価されないが、祭りの場でデジ民について講演するのは評価される。
3. 選挙時に党が指定する「ごく一部の限られた時期と場所」を除き、議員がサポーターをデジ民の実践以外の活動に **動員するのはNG**。
4. 「全議員が一律で同じ活動をするわけではない」ことをサポーターにきちんと伝える。

## 3. 現行案への懸念（対案の立場）

- 議員の活動を禁止したいわけではない。ただし現行案のままだと、**勝手に地域活動をして選挙に向けた活動をやる人が現れる**。
- 議員は地域の人の顔が浮かぶので、頼まれると断らずに行ってしまう。結果として **議員の「アイドル活動」化** が起きうる。
- デジ民に向けた活動は組織活動本部の管轄で実施できる。**個人がオフラインで動くより、本部主導のほうが広げていける**。
- 「穴が空いている状態でデジ民の話をするのは違う」（街頭活動やチラシなど、従来型の手段でデジ民を語ることへの違和感）。
- オフラインイベントは本部が開催し、そこに議員をアサインする。**各議員の個別の地域活動がそれほど重要だとは考えていない**。選挙で勝つことが目的ではないため。

## 4. 論点の整理

### 論点A: 議員発の地域活動を「推奨」するか「中立」にするか

| | 現行案 | 対案 |
|---|---|---|
| 位置づけ | デジ民の実践なら推奨 | 禁止はしないが、積極的には推奨しない |
| 主導者 | 議員個人でもよい | 組織活動本部が企画し、議員をアサイン |
| 懸念 | 選挙目的の地域活動への流出、アイドル化 | 議員の自発性・地域とのつながりを活かしきれない |

両案の実質的な違いは「議員個人が起点になってよいか」の一点に集約される。

### 論点B: サポーター動員の線引き

- 両案とも「デジ民の実践以外への動員はNG」で一致している。
- 差分は、デジ民の実践であっても **議員個人がサポーターに声をかけてよいか**。
  - 現行案: 本部に事前確認すればよい。
  - 対案: 声かけ自体を本部経由にしたい（議員→サポーターの直接動員ルートを作らない）。
- 「事前確認」は運用上ザルになりやすい（事後報告化・形式化）。実効性を持たせるには、確認を「申請と承認」にするか、動員ルートそのものを本部に一本化するかのどちらか。

### 論点C: 「評価の対象」の設計

- 現行案は「評価されるか否か」で行動を誘導する設計。
- ただし、評価されなくても地域活動は自由にできるため、**評価設計だけでは選挙目的の地域活動を抑止できない**（対案の懸念の核心）。
- 評価で誘導できるのは「やる気のある議員の努力の向き先」であり、「やってほしくない活動をやめさせる」ことではない。抑止したいなら、評価とは別にルール（禁止・要承認）が必要。

### 論点D: 「デジ民を語る手段」の適切さ

- 街頭演説やチラシでデジ民を語ることについて、「理論上は評価対象」（現行案）と「穴が空いている状態で語るのは違う」（対案）で温度差がある。
- 対案の立場をとるなら、評価対象を「デジ民プロダクトを **実際に使う** 場を作る・参加する活動」に限定し、「デジ民について **話すだけ** の活動」は評価対象外と明示するのが一貫する。
- 祭りでの講演の扱いはこの線引きで再検討が必要（講演は「話すだけ」に該当する）。

### 論点E: サポーターへの説明

- 「全議員が一律で同じ活動をするわけではない」は両案とも必要。
- 加えて対案の立場では、「議員から直接活動を頼まれても、本部を通していないものは党の活動ではない」ことをサポーターに伝える必要が出てくる。これはサポーターが議員からの依頼を断る根拠になる。

### 論点F: 地域とのつながりをどう扱うか

- 対案は「各議員の地域活動はそれほど重要ではない」と切るが、地域の人から声がかかること自体は資産でもある。
- 「行くのは自由。ただしサポーターは連れて行かない。党の活動としてはカウントしない」と明確にしておけば、議員個人の地域付き合いと党の活動を切り分けられる。

## 5. 統合案

現行案の骨格を維持しつつ、対案の懸念（議員起点の地域活動が選挙型に流れる）に対する歯止めを入れる。

### 原則

1. **デジ民の実践に関するオフライン活動は、組織活動本部が企画・運営し、議員をアサインする** ことを基本線とする。
2. 議員が自ら地域でデジ民の活動をしたい場合は、**事前に本部へ申請し、本部の活動として実施する**（本部の企画に載せる）。承認されたものは評価対象。
3. **サポーターへの声かけは本部を通す**。議員が個人的にサポーターへ参加を依頼することはしない（デジ民の実践であっても同様）。
4. デジ民の実践ではない地域活動（街頭演説、チラシ配り、祭りへの顔出しなど）は **議員個人の活動として自由**。ただしサポーターを伴わず、党の活動としては扱わず、評価対象にもしない。
5. 選挙時に党が指定する時期・場所を除き、サポーターをデジ民の実践以外に動員することは **禁止**。

### 評価対象の定義

- 評価対象: 本部の企画として実施された、デジ民プロダクトを実際に使う（または使ってもらう）活動への参加・主催。
- 評価対象外: デジ民について「話すだけ」の活動（街頭・チラシ・講演）、祭りなどへの顔出し。
- 結果は本部に共有し、本部がベストプラクティスとして集約する（現行案を維持）。

### サポーターへの伝え方

- 全議員が一律で同じ活動をするわけではない。
- サポーターへの活動依頼は本部から行う。議員から直接依頼があった場合は本部に確認してよい（断ってもよい）。

### 現行案からの変更点

| 項目 | 現行案 | 統合案 |
|---|---|---|
| 議員発のデジ民地域活動 | 推奨（本部に確認） | 本部への申請を経て本部の活動として実施 |
| サポーターへの声かけ | 議員が本部確認後に可 | 本部経由に一本化 |
| 街頭・チラシでデジ民を語る | 理論上評価対象 | 評価対象外 |
| 祭りでの講演 | 評価対象 | 評価対象外（「話すだけ」に該当） |
| デジ民以外の地域活動 | 禁止しないが評価しない | 同じ。ただし「サポーターを伴わない・党の活動ではない」を明示 |

## 6. 残論点（決めるべきこと）

1. 「申請」の運用: 誰が承認するか、リードタイム、断る基準。形式化してザルになるのを防ぐ設計が必要。
2. 議員主催のオンライン活動（配信、SNS でのデジ民プロダクト紹介など）は本方針の対象か。地域活動と同じ扱いにするか。
3. 「サポーター主催の場に議員が顔を出す」ケース: 主催がサポーターなので動員ではないが、議員が繰り返し出ることで実質的な後援会化が起きないか。本部への事前共有を条件にするか。
4. 選挙時の「党が指定する時期と場所」の具体的な決め方と、その周知タイミング。
5. 本方針を破った場合の扱い（注意、評価からの除外、その他）。
6. 議員自身への説明: 「地域とのつながりを軽視しているわけではない」ことをどう伝えるか。

## 7. アクションボードへの示唆

議員向けのミッションや評価をアクションボード上で扱う場合は、上記の「評価対象の定義」に沿って設計する。

- 評価対象となる活動は本部企画のイベントに紐づくため、ミッション達成の起点は「本部が登録したイベントへの参加・主催」にするのが自然。
- 議員が自由に達成報告できる形にすると、評価対象外の活動が混ざる。イベントIDなど本部側のデータに紐づける形が望ましい。
- 具体的な実装は本方針が確定した後に別途要件定義を行う。
