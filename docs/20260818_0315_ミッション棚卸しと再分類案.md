# ミッション棚卸しと再分類案

**このドキュメントの位置づけ**：Phase 1「ミッション体系の再整理」の実施案。全72ミッションを棚卸しし、処遇（継続・復活・選挙アーカイブ・削除統合）と新カテゴリ体系を提案する。このままYAML変更PRの仕様として使う。

親ドキュメント：[アクションボード ポータル化ロードマップ](./20260818_0237_アクションボードポータル化ロードマップ.md)

## 1. 現状サマリ

| 指標 | 値 |
|---|---|
| 全ミッション数 | 72本 |
| 表示中 | 48本 |
| 非表示 | 24本（選挙用の使い捨て・終了イベント含む） |

| 表示中のフォロー・いいね系 | 18本（38%） |
| 表示中の「1回きり・難易度1」 | 15本 |

### 構造的な問題

1. **カテゴリがプラットフォーム別**：現在の16カテゴリは「Xで応援」「TikTokで応援」「YouTubeで応援」「noteで応援」…とチャネル別に並んでいる。露出最大化という選挙期の目的には合っていたが、「自分は何をしたい人か」でミッションを探す平時の使い方に合わない。
2. **1回きりミッションが入口を塞いでいる**：難易度1・1回きりのフォロー系15本は登録直後に消化され尽くし、その後にやることが見えなくなる。「毎週やりたくなる」設計になっていない。
3. **featured運用が止まっている**：おすすめ表示は1本のみ。「今週のおすすめ」を回す運用がない。
4. **メンテナンス漏れ**：終了した日付イベント（7/3街頭みらい会議、7/19マイク納め）や重複ミッション（期日前投票が2本）が非表示のまま残置。カテゴリ紐付けのないミッションも5本ある。

## 2. 新カテゴリ体系案 — 「関わり方」別の6分類

チャネル別ではなく、サポーターの関わり方タイプで分類し直す。Phase 1の「関わり方診断」はこの6分類にそのまま接続する。

| 新カテゴリ | 対象者イメージ | 本数（継続＋復活） |
|---|---|---|
| 🚪 はじめの一歩 | 登録したばかりの人 | 6本 |
| 📱 すきま時間で応援 | 見て・押して応援したい人 | 18本 |
| 📣 発信して広げる | SNSで発信したい人 | 6本 |
| 📖 学ぶ・政策に関わる | 政策に興味がある人 | 16本 |
| 🏘️ 地域で動く | 地域の活動に参加したい人 | 10本 |
| 🛠️ スキルで貢献する | 開発・デザイン・企画で手を動かしたい人 | 4本 |

ポイント：**政策クイズ5本の復活で「学ぶ・政策に関わる」が16本の主力カテゴリになる**。政策への接点は「デジタル民主主義の実現」という本来の目的に最も直結する体験であり、選挙がない平時のメインコンテンツに据える。

## 実装メモ（YAML変更PRの仕様）

1. **`categories.yaml`**：新6カテゴリを追加（既存16カテゴリは当面残し、`category_links.yaml` の紐付けを新カテゴリに切り替えてから旧カテゴリを整理する。2段階に分けると差分がレビューしやすい）。
2. **`missions.yaml`**：復活12本の `is_hidden: false` 化（要確認5件はクリア後）。文言が選挙仕様のものは平時向けに更新。
3. **`category_links.yaml`**：全ミッションを新カテゴリに紐付け直し。削除・統合対象はリンクを外すのみ。
4. **物理削除はしない**：`mission:sync` がYAMLから消えたミッションをDB側でどう扱うかが未確認であり、達成履歴（`achievements`）が紐づくミッションの削除はデータを壊すリスクがある。削除・統合対象も**YAMLに残して `is_hidden: true` のまま**とし、コメントで処遇を明記する。
5. **選挙アーカイブはYAML内コメントでブロック化**：`# --- 選挙アーカイブ（次回選挙で復活） ---` のように区分し、次の選挙時に一括で `is_hidden: false` にできる状態を保つ。
6. **featured運用の再開**：「今週のおすすめ」として2〜3本を `is_featured: true` にする週次運用を開始（YAML編集のみ、コード変更不要）。

## PR分割案

- **PR-1**：新カテゴリ追加＋全ミッションの紐付け直し＋削除・統合対象のリンク外し（表示の変化：カテゴリ構造が変わる）
- **PR-2**：復活12本の表示化＋選挙仕様文言の平時化（要確認5件の回答が揃い次第）
- featured週次運用はPRを分けず、以後の運用として実施
