# リーダーチーム再始動ロードマップ

## この資料の位置づけ

- **目的**: リーダーチーム運営規程の施行〜新体制スタート（9/14）までを、同じ地図を見ながら進められるようにする。「今どこにいて」「何を」「どの順番で」「誰が」決めるのかを揃え、**あわせて「今回は解かない」ことも明示して合意する**。
- **スコープ外にすること自体がこの資料の役割の一つ**。全部やろうとするとキャパシティを超え、9/14に間に合わない。「後で困るが今は割り切る」ことを同じ理解で受け入れるための資料。

参照した一次情報：
- リーダーチーム運営規程（案）
- 現リーダーチームへのAIインタビュー集約レポート（54名分）
- リーダーチームMtgのチャット分析（名称変更・お試し期間・エリア区分・地域戦略に関する討議）
- 確定スケジュール（8/27, 9/9, 9/11, 9/14）
- 名称変更（RCV）・エリア区分・立替払い・再結成の進め方に関する追加決定事項

## 1. 現状の立ち位置

### 決まっていること（動かせない制約・すでに決定済みの方針）

| 項目 | 内容 |
|---|---|
| スケジュール | 8/27 継続意思確認をSlackで案内 → 9/9 フォーム回答締切 → 9/11 新体制発表 → 9/14 新体制スタート（変更不可） |
| 継続の原則 | 継続を希望し要件（第5条）を満たす現メンバーは全員継続。回答がなければ一旦登録解除（再加入はいつでも歓迎）。ふるい落としの場ではない |

| 規程の骨格 | 役割定義・エリア14区分・任期/解散再結成・退任手続き・相談窓口などは案として作成済み |

| 開票・結果発表 | 開票のライブ配信は行わず、「◯月◯日◯時に◯◯で発表します」と事前に告知した日時・場所で結果を発表する |

### 決まっていないこと（大きな論点）

規程の構造に関わる論点をここに、運用レベルの細かな未決事項は**5章のバックログ**に棚卸しした（拾い漏れ防止のため、インタビュー由来の細目もすべてそちらに記載）。

| 論点 | 規程案の状態 | 現場からの主な指摘 |
|---|---|---|
| お試し期間の長さ | 一律3ヶ月 | Mtgでは2〜3ヶ月が優勢。「期間 vs タスク量」の二軸あり |
| お試し期間中に何をするか／合否基準 | 「本部が資格要件・行為・役割適合性を踏まえ判断」とだけ規定 | 基準が曖昧だと「本部に都合の良い人だけ残る」という不信感リスクが複数箇所で指摘 |
| 休止ステータス | 規程に記載なし（退任か非稼働整理の二択しかない） | 病気・介護・農繁期など、一時的に活動できない人の「休み」扱いを求める声が複数（#36, #2, #12, #38） |
| 「調整・支援役」と現場実態の乖離 | 権限を持たない補助役と規定 | 選挙時は事実上の指揮・決定が必要になる、との指摘 |
| インセンティブ設計・活動評価 | 規程に記載なし | 「報われないと優秀な人ほど離れる」という懸念 |
| 地方支部・党とサポーターの将来的関係 | 規程に記載なし | 支部設置の有無自体が未表明、という指摘 |
| フェーズ別の地域戦略設計 | 規程に記載なし | 「認知→サポーター化→参加→深い関与」の段階ごとに地域戦略を分解すべき、という提起（ながたK氏） |

## 2. 何を解くか／解かないか

同じ土俵で全部を扱うと収拾がつかないため、次の3つに仕分けて合意する。

### A. 9/14までに答えを出す（新体制のスタート・8/27送付物に必須）

これがないと8/27の案内が送れない、9/14に新体制を開始できない、または新規メンバーの受け入れが初日から止まる論点。

1. **お試し期間の長さと合否基準**（規程案の第6条の運用ルール確定）
2. **お試し期間中に何を「お試しした」とみなすか**（合否基準の透明化）
3. **見送り（本格加入させない）の判断プロセスと通知の型**（本部決定＋地域推薦を参考、という方向性を運用手順に落とす）
4. **8/27フォームの設計**（継続／休止／退任の選択肢を設けるか、退任・休止の導線、Slackに加えLINEを併用するか）
5. **継続意思確認の実務**（リマインド設計・一人一回回答の担保）
6. **RCVの実施準備**（候補名の確定、投票システム・一人一票の担保・通知方法。8/27に実施案内を同送するため、ここがクリティカルパス）

→ 1〜3は規程第6条、4〜6は8/27の送付物に直結するため、**優先度が最も高い**。

### B. 9/14の必須条件にはしないが、並行して整える実務

1. **立替払い（道路使用許可）の運用フロー確定**：対象範囲は決定済み。既存の申請フォームを使った申請〜精算までの手順を明文化し、リーダーチームへ周知する
2. **運用ガイド（Q&A）の整備**：非稼働の定義・応答期間、クローズド連絡の線引き、連絡経路など（5章バックログの「運用ガイドで決める」群）。9/14までにドラフト、新体制発足後に公開・更新

### C. 今回は着手しない（次の規程改定サイクル・別の意思決定体に委ねる）

明確に「今回は解かない」と決め、その理由とともにメンバーに伝えるべき論点。

| 論点 | 今回扱わない理由 | 対応方針（本部提案。6章参照） |
|---|---|---|
| インセンティブ設計・予算配分（政党交付金モデルの参照など） | 財務・組織全体の設計マターであり、9/14の体制発足とは切り離して検討すべき規模の論点 | 非金銭的な承認（月次活動報告での言及、Action Boardのバッジ等）は即時開始。制度検討は中間棚卸し（12月目安）までにワーキンググループを組成し着手する期限を今日宣言する |
| 地方支部設置・党とサポーターの関係性の再定義 | 党全体の組織戦略に関わり、組織活動本部だけで完結しない | 党の意思決定層（代表・幹事等）へ照会メモを提出し、回答期限を設定する。メンバーには「認識しており党全体で検討を依頼している」旨だけ伝える |
| エリア14区分そのものの再編 | 区分は確定区分として維持することを決定済み。個別の実情（例：宮城/福井の担当分け）は都度の個別対応で吸収する | ─（決定済みのため対応不要） |
| フェーズ別の地域戦略設計（ながたK氏提起） | 重要な指摘だが、今回のスコープ（規程再始動）より一段上の中期テーマ。持ち帰り、別枠で検討時間を確保する | 「持ち帰る」で終わらせず、提起者本人を含むワーキングセッションを9/14キックオフ後1〜2ヶ月以内に1回開催することを今日確定し、担当者を割り振る |
| 規程本文の抜本的な書き直し（分量・厳格さへの賛否など） | 大枠は据え置き、9/14の運用に支障が出る条文のみ最小限修正する（第6条の運用ルール明確化が中心） | ─（対応不要） |

**この仕分けをそのまま8/27前の合意事項とし、9/11の新体制発表・9/14のキックオフでも「今回決めたこと／次回以降に持ち越すこと」として一言添えられるようにしておく。**これをしないと、アンケートで既に出ている「都合よく運用されているのでは」という不信感（見送り基準の曖昧さ、クローズドな場での決定への懸念）を再燃させるリスクがある。

## 3. 進め方（順序とタスク）

固定スケジュールを起点に、逆算して並べる。全体の流れ：**規程のスライド化 → 既存メンバーの意思確認＋RCV案内（8/27同時送付）→ RCV投票・開票 → 9/11新体制発表 → 9/14キックオフ → 新規募集を随時受付で開始**。

### Phase 0：〜8/26（意思決定・送付物の準備）

- [ ] 運営規程のスライド化（8/27案内・説明会・9/14キックオフで共通利用する説明資料）
- [ ] お試し期間の運用ルールを合議で確定：長さ／合否基準／再加入時の免除の扱い
- [ ] 見送り時の通知プロセス（誰が・どう伝えるか・記録の残し方）を確定（規程第6条4項の運用手順化）
- [ ] 8/27フォームの設計（継続／休止／退任の選択肢、LINE併用の可否、一人一回回答の担保）
- [ ] RCVの準備（候補名の確定、投票システム・一人一票の担保・通知方法。党大会でのRCV実績の流用可否を確認）
- [ ] 立替払い（道路使用許可）の運用フローのドラフトを準備（既存フォームの案内文を含める）
- [ ] 8/27送付物（継続意思確認＋RCV実施案内＋規程スライド）の最終確認

### Phase 1：8/27〜9/9（意思確認＋RCV投票の実施期間）

- [ ] 8/27 継続意思確認（既存メンバー向け）＋RCV実施案内（全サポーター向け）を送付（Slack・LINE）
- [ ] 名称の説明会を実施（希望者向け、8月末〜9月上旬目安）
- [ ] RCV投票期間（〜9/8目安。9/11の発表に載せるための逆算）
- [ ] 未回答メンバーへのリマインド（9/2・9/8の2回目安）
- [ ] Phase 0で確定したお試し期間ルールを、新規加入フォーム・案内文に反映
- [ ] 立替払い（道路使用許可）の運用フローを確定

### Phase 2：9/9〜9/11（集計・開票・発表準備）

- [ ] 9/9 フォーム回答締切、集計、新体制メンバーリストの確定
- [ ] RCV開票。結果発表の日時・場所を事前告知（ライブ配信はしない）
- [ ] 9/11 新体制発表（可能なら新名称も同時に発表。「決まったこと」と「引き続き検討すること（2章C）」を分けて伝える）

### Phase 3：9/11〜9/14（発表〜キックオフ）

- [ ] 9/14 キックオフ（参加者集合）：新体制の顔合わせ、規程スライドの共有、お試し期間の運用説明、新規募集を開始することの告知

### Phase 4：9/14以降（新規募集・継続検討）

- [ ] 新規募集をフォームで開始。**締め切りは設けず随時受付**。新メンバーはちょこちょこ集まってくる前提で、月次のお試し満了バッチ（第6条）で回す
- [ ] 立替払いフローをリーダーチームへ周知
- [ ] 運用ガイド（Q&A）を整備・公開（5章バックログの「運用ガイドで決める」群）
- [ ] 2章Cの中長期論点（インセンティブ・支部・地域戦略設計）を、次の検討サイクルに乗せるための場を設定する（例：中間棚卸し時、または次回の規程改定〔第14条〕のタイミング）

## 4. 意思決定の型（誰がどう決めるか）

Mtgでの議論を踏まえ、論点ごとに決定の型を揃えておく。

- **お試し期間の合否・本格加入の可否**：本部決定＋地域推薦を参考にする（本部が最終権限を持つが、独断にしない）
- **名称変更**：全サポーター対象のRCV投票で決定。事前に説明資料（Slack・LINE）＋希望者向け説明会。開票は事前告知した日時・場所で結果発表（配信なし）（決定済み）
- **再結成の進め方**：既存メンバーのフォーム確認を先行 → 9/14キックオフ → 新規募集は随時受付で締め切らない（決定済み）
- **エリア区分**：現行14区分を確定区分として維持し、実情に合わない部分は個別対応で調整する（決定済み）
- **立替払い**：道路使用許可のみ例外的に立替を認める（決定済み）。運用フローの確定はPhase 0〜1で進める
- **中長期の組織設計論点（2章C）**：この場では決定しない。持ち帰り、検討の場を別途設定することだけを今回決める

## 6. 論点ごとの本部提案（意思決定案）

1章「決まっていないこと」の7論点について、組織活動本部としての意思決定案をまとめる。**まだ全員の合意を得た決定ではなく、提案（叩き台）**。判断軸は、インタビュー・Mtgでの多数派/少数派の意見に加え、運営工数と後戻りしやすさ（リバーシビリティ）。

| 論点 | 提案する意思決定 | 主な根拠 |
|---|---|---|
| お試し期間の長さ | **3ヶ月固定**（期間基準のみ、タスク量基準は採らない） | Mtg最多。ながたK氏「本部が経過を見るには3ヶ月、最低2ヶ月」。タスク量基準は地域差・閑散期差で不公平になり、判断工数が増える |
| 合否基準 | **デフォルト合格＋最小限の客観ゲート**：①既存メンバーとの顔合わせ1回 ②Don't/禁止行為の記録可能な違反がないこと。両方満たせば自動承認。本部協議は「地域から懸念申告」「第5条要件不備」の2ケースのみ | 「見送り基準の透明性」が最重要課題という指摘に対応。アクションボードのポイント等の主観指標は参考情報止まりとし、正式基準化しない（閑散期加入者が構造的に不利になるため） |
| 休止ステータス | **自己申告制、承認プロセスなし**。8/27以降のフォームに「継続（通常）／継続（休止）／退任」の3択を追加。休止選択者は一定期間（例：6ヶ月）非稼働整理サイクルの対象外にする | 要望した全員が「一時的に無理なだけ」という状況。規程の条文改定は不要で、フォームの選択肢追加のみで対応可能 |
| 「調整・支援役」と実態の乖離 | 規程の文言は変更せず、**「時限的委任」の運用ルール**を新設。選挙期間中など限定的な場面で、本部が記録付き・撤回可能な意思決定権限を該当メンバーへ委任し、事後報告する。まず選挙期間のみで試験導入 | 恒久的な権限構造の変更は大手術（Category C）。一方で選挙が来る前に何もしないと同じ問題が再発する。時限・記録・撤回可能な形にすれば第1条の大原則を守れる |
| インセンティブ設計・活動評価 | 制度設計はCategory C継続。ただし**検討開始の期限を今日宣言**（中間棚卸し・12月目安までにワーキンググループ組成）。非金銭的な承認（月次活動報告での言及、Action Boardのバッジ表示等）は即時開始 | 懸念の核は「報われない感覚」であり、必ずしも金銭的インセンティブが必要ではない。金銭的設計は政治資金規正法との整合確認が要り拙速はリスク。期限を示さない「持ち帰り」が不信感の根 |
