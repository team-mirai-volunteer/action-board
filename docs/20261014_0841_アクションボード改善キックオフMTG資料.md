- 指標の目標値（水準は今後の実測値をもとに検討、という10/7の整理に従う）

## 2. 前提の共有：10/7にサポーターへ約束したこと

10/7スライドで、サポーター向けに以下を公式に伝えている。アクションボードはこの約束を実装する場になる。

### 2-1. 方針（p.10, p.18）

- この1年は「デジタル民主主義を徹底して実践する1年」にする。
- これまでの「チームみらいを広げる活動」から、「デジタル民主主義を実践する活動」へ。
- 「聴く→磨く→動かす→伝える」のサイクルを回す。

### 2-2. 戦略：2つの輪（p.19〜21）

- **内輪（体験の輪）**: 場に参加する → 意見を寄せる → 扱われ方が分かる → また参加する・次は自分で開く
- **外輪（広める輪）**: 知る → 関心をもつ → 人に勧める → 新しい人が知る
- 党は「情報やツールを用意する」側。外輪で知った人が内輪の場に参加し、参加した人がまた外輪で伝える。

### 2-3. 12月までの目標（p.22）

| 目標 | 回数 |
| --- | --- |
| 党主催の会 | 5回以上 |
| サポーター主催の場 | 15回以上 |

サポーターへのお願い: 「場に参加する」「自分で場を開く」「改善点を伝える」

### 2-4. 重視する指標（p.24）

**北極星（向こう1年）**: デジタル民主主義を実践する場の、のべ参加人数
（ただし再訪率を重視し、2回目の参加率が一定水準を下回らないことを条件とする）

**北極星の達成のために重要な指標**:

- 初参加の人数（新規流入があるか）
- 外輪経由の初参加数（発信をみて場に来た人数）
- 2回目参加率（内輪の継ぎ目指標）
- 紹介率（誘われて来た参加者の割合）
- イベントを主催するサポーターの数と、サポーター主催の開催数
- **外輪アクション実施数と実施ユニーク人数（アクションボードで計測）** ← スライド上で明示的にアクションボードの担当
- 初参加の後に何らかの返答が返ってくるまでの日数

**追わない指標**: サポーター登録数の総量 / 再訪の導線がない単発イベントの動員数

### 2-5. 4つの関わり方（p.26〜43）

| --- | --- | --- | --- |

| 02 | 場に参加する | 党やサポーターが開く場に参加し意見を出し合う | 「アクションボードなどから、参加できる場を見つけやすくする。開催予定の場を一覧で探せるようにします」（p.30） |

### 2-6. アクションボードのリニューアル告知（p.43）

- ミッションの中身が「ポスター貼りやポスティングなど選挙の活動」から「4つの関わり方に合わせた活動」に変わる。

## 3. アクションボードの位置づけの再定義

### 3-1. 位置づけ（案）

> アクションボードは、チームみらいのサポーターが **デジタル民主主義を実践するためのボード** である。
> サポーターは4つの関わり方に沿ったアクションをここで見つけ、実行し、その結果が見える。
> **アクションボードに登録している人＝チームみらいのサポーター** として扱う。

### 3-2. これまでとの違い

| 観点 | これまで | これから |
| --- | --- | --- |
| 目的 | チームみらいを広げる（選挙・認知拡大） | デジタル民主主義を実践する |
| 主なアクション | SNSフォロー・拡散、ポスティング、ポスター貼り、街頭演説 | 4つの関わり方（知る・意見を寄せる / 場に参加する / 誘う・伝える / 場を開く） |
| 登録の意味 | 活動したい人が任意で登録 | 登録＝サポーターという整理 |
| 評価 | ポイント・レベル・ランキング（活動量） | 北極星（場ののべ参加人数）と関連指標に寄与するか |

### 3-3. 論点

- **「登録＝サポーター」の整理で、既存のサポーター導線（公式LINE、Slack、HubSpot等）との関係はどうするか。** サポーター登録数の総量は「追わない指標」だが、母集団の定義として必要。
- **選挙系ミッションの扱い。** 現状のボードには「街頭演説に参加しよう」「活動報告をポスティングしよう」「街頭でチラシを配布しよう」「街頭演説を手伝おう」「私有地ポスターを掲示しよう」が表示中。10/7の整理（党・議員の認知拡大目的の活動は優先度を下げる、新規の政党ポスター掲示は一旦ストップ、ポスティングは春以降）に合わせて、非表示・文言変更・残置のどれにするか。
- **既存のポイント・レベル・ランキング・シーズンをどう位置づけるか。** 「現在のポイント機能は引き続き提供」と伝えているので廃止はしないが、デジ民の活動に重みを置くのか。

## 4. 全体像：アクションボードが満たすべき6つの要素

細かい機能の話に入る前に、「アクションボードとして成立するために何が揃っている必要があるか」を6つの要素で整理する。以降の改善テーマはすべてこのどれかに紐づける。

```
 ┌──────────────────────────────────────────────────────────────┐
 │  ⑥ 更新できる（運営が、やってもらうことを継続的に入れ替えられる）   │
 │   ┌──────────┐   ┌──────────┐   ┌──────────┐                   │
 │   │ ① 見つける │ → │ ② できる   │ → │ ③ 報われる │                   │
 │   │ やることが │   │ 必要な情報 │   │ やると良い │                   │
 │   │ 並んでいる │   │ が揃っている│   │ ことがある │                   │
 │   └──────────┘   └──────────┘   └──────────┘                   │
 │         ↑                              │                         │
 │   ┌──────────┐                  ┌──────────┐                   │
 │   │ ⑤ 促せる  │ ←──────────────  │ ④ 測れる  │                   │
 │   │ 次の一歩を │                  │ 使われたか │                   │
 │   │ 後押しする │                  │ 効いたかが │                   │
 │   └──────────┘                  │ 分かる     │                   │
 │                                  └──────────┘                   │
 └──────────────────────────────────────────────────────────────┘
```

| # | 要素 | 意味 | 10/7の約束との対応 | 現状（2026/10/14時点） |
| --- | --- | --- | --- | --- |
| ① | **見つける** | 4つの関わり方ごとに、やること（ミッション）が並んでいる | p.28「関わり方ごとに一覧で見つけられる」、p.43 | ミッション72件（うち非表示24件）。カテゴリ16個はSNS応援・フォロー中心で、4つの関わり方の軸ではない |
| ② | **できる** | やるのに必要な情報（場の案内、ガイド、テンプレ、申請方法）が揃っている | p.30「開催予定の場を一覧で探せる」、p.33「紹介・発信に使える情報をまとめる」、p.35〜39 場を開く方法 | 「イベントに参加しよう」ミッションはあるが、場の一覧はボード上にない。ガイド類もボード外（Slack / LINE / 配信） |
| ③ | **報われる** | やると良いことがある（ポイント、バッジ、見える成果、お礼） | p.43「デジタル民主主義ポイント（検討中）」 | ポイント・レベル・バッジ・ランキング・シーズンは稼働中。内容は活動量ベース |
| ④ | **測れる** | 機能が使われたか、北極星・関連指標に効いたかが分かる | p.24「外輪アクション実施数と実施ユニーク人数（アクションボードで計測）」 | 達成ログ・BigQuery連携・流入元（campaign attribution）・紹介（referral）は実装済み。「場への参加」はボード上で記録されていない |
| ⑤ | **促せる** | お知らせ・通知で次の一歩を後押しできる | p.43「お知らせと通知」、p.58「メール活用」 | お知らせは固定バナーのみ。通知はバッジ獲得の画面内表示のみ。LINE・メールのプッシュ通知はない |
| ⑥ | **更新できる** | 運営が、やってもらうことを継続的に追加・入れ替えできる | p.43「順次、機能を追加・変更」 | ミッション・カテゴリはYAMLで宣言管理、デプロイ時に自動同期。運営側がコードを触らずに更新する手段はない |

**議論したいこと**

- この6要素で抜け漏れはないか。
- どの要素から手をつけるか。PM案は「① 見つける → ④ 測れる → ⑤ 促せる」の順（約束の実装と、計測できる状態を先に作る）。
- 「② できる」のうち、場の一覧（イベント一覧）をアクションボードに持つのか、別の場所（公式LINEのイベント予定など）に任せてリンクするだけにするのか。

### 4-1. 4つの関わり方 × 現状ミッションの対応（叩き台）

| 関わり方 | 現状のミッションで対応しそうなもの | 不足しているもの（例） |
| --- | --- | --- |
| 01 知る・意見を寄せる | マニフェストを見る、みらい議会を見る、公式YouTube・note、クイズ | AIインタビューに回答する、法案ごとのAIインタビュー、デジ民を知るコンテンツを見る |

## 5. 計測：追う指標とアクションボードで取れるもの

### 5-1. 前提

- 組織活動本部（そかつ）が追うKPIがあり、必要に応じて広聴のKPIとも揃える（要確認）。
- アクションボード上でKPIが計測できる必要がある。KPIそのものだけでなく、関連する指標も取れるようにしたい。
- **何を計測するかはまだ整理されていない。** この会では「整理の進め方と担当」を決める。

### 5-2. p.24 の指標をアクションボードの観点で仮分類

| 指標 | アクションボード単体で取れるか | 取るために必要なこと |
| --- | --- | --- |
| 外輪アクション実施数・実施ユニーク人数 | **取れる**（ミッション達成ログ） | 「外輪アクション」に当たるミッションを定義する |
| 紹介率（誘われて来た割合） | 一部取れる（紹介機能、流入元記録） | 「場への参加」と紹介の紐づけ |
| 初参加の人数 / 2回目参加率 | **取れない**（場の参加記録がない） | 場の参加をボード上で記録する仕組み（参加ミッション or イベント参加登録） |
| 外輪経由の初参加数 | 取れない | 上記 + 流入元の記録 |
| 主催サポーター数 / サポーター主催の開催数 | 取れない | イベント登録・申請フローとボードの接続 |
| 初参加後に返答が返るまでの日数 | 取れない | 運営側の対応記録 |

### 5-3. 論点

- 「場への参加」をアクションボードで記録する前提で設計するか。記録するなら、参加者自身の自己申告（ミッション達成）か、主催者側の参加者登録か、イベント登録フォームとの連携か。
- 指標の定義書を誰がオーナーとして書くか（PM案: 組織活動本部がKPI定義、PM・開発が計測設計）。
- ダッシュボードはどこに出すか（現状のstatsページ、BigQuery側、別ツール）。

### 6-2. 開発の回し方（現状と提案）

- 現状: PMがClaude（AI）と壁打ちしながら要件を固め、PRを作成する体制。小さな変更は本部側の確認を挟まず出せている。
- 提案:
  - **ミッション・カテゴリの入れ替えはYAML変更のみで済む**ので、本部からの依頼を受けてPMがPRを出す形を標準にする。
  - 機能追加（お知らせ・通知、場の一覧、計測）は、先に短い要件ドキュメントを `docs/` に置き、本部の確認を取ってから実装に入る。
  - 週1回、進捗と次に出すものを確認する短い定例を置く（Slackの非同期でも可）。
- 確認したいこと: 本部側が確認したい粒度（すべて見る / 機能追加だけ見る / 事後報告でよい）。
